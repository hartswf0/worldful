TITLE:
Interpretive Flexibility Alone Does Not Make the Yellow Circle a Boundary Object

SOURCE:
Susan Leigh Star - “This Is Not a Boundary Object: Reflections on the Origin of a Concept” - 2010. ([Sage Journals](https://journals.sagepub.com/doi/pdf/10.1177/0162243910377624?utm_source=chatgpt.com)) ([Canonical Link](https://doi.org/10.1177/1075547010376049))

PASSAGE:
[QUOTE]
"Boundary objects are not simply 'anything that connects two groups.' Boundary objects arise from the tension between local tailored use and standard cross-site needs. They allow cooperation without consensus." — Susan Leigh Star, This Is Not a Boundary Object: Reflections on the Origin of a Concept, Science, Technology, & Human Values, 35(5), pp. 601–617 (2010)

RESEARCH OBJECT:
Whether the Yellow Circle can legitimately be treated as a boundary object across SVG, Logo, GUI, model, designer, and user practices.

LOCAL MOVE:
Blocks the easy claim that the Yellow Circle is a boundary object merely because several communities interpret it differently.

SOURCE TERMS:
boundary object; interpretive flexibility; work process; ill-structured; tailored use; infrastructure.

WHAT BECAME STRANGE:
The Yellow Circle only becomes a boundary object in Star’s stronger sense if heterogeneous communities actually organize cooperative work through it while retaining locally different structures around it.

QUESTION:
What work arrangement would make the Yellow Circle a genuine boundary object rather than simply a polysemous artifact?

DEEPER QUESTION:
Can one invariant artifact coordinate heterogeneous programming-language communities without requiring consensus about what the artifact fundamentally is?

MECHANISM:
A common object remains sufficiently robust for coordination while being differently structured for local work; standardization and local tailoring permit cooperation without semantic identity.

FORMAL SHIFT:
SAME ARTIFACT + DIFFERENT INTERPRETATIONS → BOUNDARY OBJECT
becomes
SHARED ARTIFACT + HETEROGENEOUS LOCAL PRACTICES + COOPERATIVE WORK ARRANGEMENT → POSSIBLE BOUNDARY OBJECT.

SOURCE FORMALISM:
Star distinguishes interpretive flexibility from the fuller architecture of boundary objects.

OUR FORMALIZATION:
[OUR FORMALIZATION - NOT SOURCE SYNTAX]
YELLOW_CIRCLE is a boundary object only if:
1. multiple local language-games operationalize it differently,
2. participants coordinate consequential work through it,
3. sufficient common identity persists across those uses,
4. local representations may become more structured than the shared form.

TENSION:
The Yellow Circle experiment currently guarantees representational heterogeneity but not genuine inter-community cooperation.

MISSING:
A multi-actor experiment in which participants with incompatible representations must jointly preserve one Yellow Circle artifact.

BOUNDARY:
Do not use “boundary object” as a synonym for ambiguous, flexible, or multiply represented object.

CITATION TRAIL:
Star and Griesemer 1989 → Star 2010 retrospective qualification → Yellow Circle → Brooks conceptual integrity.

TEST:
Assign SVG, Logo, GUI, and prompt operators different local representations and require them to jointly modify one shared Yellow Circle without sharing source formalisms; observe whether the shared artifact supports cooperation.

PLATFORM:
STS / CSCW / programming-language comparison.

ZET-MATURANA-EXPLANATION-NOT-REDUCTION-2002

TITLE:
A Generative Explanation Does Not Collapse the Explained Phenomenon Into Its Mechanism

SOURCE:
Humberto Maturana Romesín - “Autopoiesis, Structural Coupling and Cognition” - 2002. ([Reflexus](https://reflexus.org/wp-content/uploads/Autopoiesis-structural-coupling-and-cognition.pdf))

PASSAGE:
Maturana states explicitly that explanations “do not constitute, and cannot constitute, phenomenal reductions.”

RESEARCH OBJECT:
The stopping rule for operational audits.

LOCAL MOVE:
Blocks the assumption that descending from prompt to API to rasterizer to pixels reveals progressively “truer” versions of the circle.

SOURCE TERMS:
explanation; generative mechanism; operational domains; phenomenal reduction; observer.

WHAT BECAME STRANGE:
Recovering the mechanism that generates an artifact does not automatically replace the higher-level phenomenon with that mechanism.

QUESTION:
Where should an operational audit stop if no lower implementation layer possesses privileged ontological status?

DEEPER QUESTION:
Can the audit preserve generative dependence without turning dependence into reduction?

MECHANISM:
Observer-accepted generative mechanisms can explain phenomena while mechanism and phenomenon occupy distinct operational domains.

FORMAL SHIFT:
LOWER LEVEL = TRUE OBJECT → LOWER LEVEL = ONE GENERATIVE DOMAIN RELATED TO ANOTHER.

SOURCE FORMALISM:
Explanations propose generative mechanisms without requiring phenomenal reduction.

OUR FORMALIZATION:
[OUR FORMALIZATION - NOT SOURCE SYNTAX]
TRACE representation boundaries until the research question no longer changes, not until a supposedly final ontological substrate is reached.

TENSION:
Operational explanation still requires causal adequacy; anti-reduction is not permission to treat all descriptions as equally explanatory.

MISSING:
A precise audit stopping criterion based on explanatory gain.

BOUNDARY:
Maturana’s philosophical account does not itself specify software tracing methodology.

CITATION TRAIL:
Maturana 2002 → operational audit → Yellow Circle stack.

TEST:
For each added implementation layer, ask whether it changes the set of possible failure explanations or experimental predictions; stop when further layers only redescribe already-accounted causal relations.

PLATFORM:
Philosophy of explanation / software studies.
